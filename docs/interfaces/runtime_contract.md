## 工具面

对 agent 暴露两个工具：

| 工具 | 作用 | 输入 | 输出 |
| --- | --- | --- | --- |
| `js` | 在持久运行时中执行一段 JavaScript | 源码字符串 | 见[输出通道](#输出通道) |
| `js_reset` | 丢弃运行时与全部绑定，重建干净环境 | 无 | 确认 |

**没有第三个工具。** 全部能力通过运行时注入的对象提供，
不通过新增工具暴露。这是 [ADR-0002](../decisions/adr_0002_code_mode_surface.md) 的核心取舍。

## 输出通道

三条通道，职责不重叠：

| 通道 | 形式 | 用途 | 是否占用预算 |
| --- | --- | --- | --- |
| **返回值** | 最后一条表达式的求值结果 | 快速查看一个值 | 是 |
| **显式文本** | `scu.write(text)` | 结构化输出、多段结果 | 是 |
| **图像** | `scu.emitImage(bytes, mimeType)` | 把截图交给模型看 | 否（走独立通道） |

### 为什么图像单独一条通道

截图是**给模型的多模态输入**，不是文本输出。若把它序列化成 base64 放进文本，
会消耗大量文本预算却表达不了图像语义。

因此 `emitImage` 与文本分开：它把图像作为附件投递给模型，
不计入文本输出预算。

### 输出预算

`js` 的文本输出有 token 上限（量级参考：数万 token）。
超出上限时**截断并明确标注截断**，不静默丢弃。

**截断必须可见。** 静默截断会让调用方以为拿到了完整数据，
进而做出基于缺失数据的判断。返回结果中需要标明"已截断"以及原始长度。

超大结果应当由调用方主动分页或聚合——这是调用方的责任，
但 SCU 必须让截断这件事可见。

## 执行模型

### 持久运行时

运行时在会话内**持久**：变量、函数、已绑定的目标句柄跨 `js` 调用存活。

```js
// 第一次调用
const app = await scu.getApp("NeteaseMusic");
const st = await app.getAXState();

// 第二次调用：app 仍然可用
await app.click("AXTextField#t7");
```

持久性是可组合性的前提——调用方可以在一次调用里探索、在下次调用里基于
上一轮的结果继续，而不用重复建立上下文。

### 返回值的语义

`js` 的返回值是**最后一条表达式的求值结果**，与交互式 REPL 一致。

这是刻意的：它让"只想看一眼某个值"的场景不需要写 `scu.write(...)`。
需要输出多段内容或结构化数据时用 `scu.write`。

**返回值与 `scu.write` 的输出不互相替代，也不重复。** 实现时需保证
同一个值不会既出现在返回值里又出现在文本通道里。

### 异步

`js` 的输入可以包含顶层 `await`。动作类 API 全部返回 Promise。

## 沙箱边界

运行时**不是**通用 Node 环境。默认能力：

| 能力 | 允许 | 理由 |
| --- | --- | --- |
| SCU 会话 API | ✓ | 唯一目的 |
| 计算、数据结构、控制流 | ✓ | 组合能力的必要条件 |
| 定时器 | ✓（有上限） | 显式等待需要 |
| 文件系统 | **✗** | 见下 |
| 网络 | **✗** | 见下 |
| 子进程 | **✗** | 见下 |
| 环境变量 | **✗** | 可能含凭据 |

### 为什么禁止文件与网络

这不是为了防范 agent——agent 本身有这些能力，它想用可以在自己的工具里用。
禁止的理由是**范围一致性**：

[ADR-0010](../decisions/adr_0010_ui_automation_only.md) 把 SCU 限定为 UI 自动化。
若运行时能读文件与联网，SCU 就变成了一条绕过界面直接访问数据的通道——
而这条通道**不受策略层约束**（策略层判定的是 UI 动作）。

把两者分开的实际收益是安全边界清晰：SCU 的权限需求收敛为
辅助功能与屏幕录制两项，不需要为运行时开放更多。

### 需要在运行时里处理数据怎么办

数据应当由**调用方**在自己的环境里准备好，作为动作参数传入。
例如要输入一段文本，由 agent 读取文件后传给 `scu.typeText`，
而不是让运行时去读文件。

## 超时与取消

### 超时

每次 `js` 调用有上限时长。超时后：

- 调用返回超时错误
- **运行时状态被标记为可疑**（见下）

超时值需要足够长以容纳正常的动作序列（含[收敛等待](../architecture/action_convergence.md)），
又足够短以在死循环时及时回收。具体取值待定。

### 死循环

运行时的循环不会被执行预算中断（不做指令级插桩，成本过高）。
因此**死循环只能靠超时终止**。

超时终止后，正在等待的 Promise 被拒绝，正在执行的动作被执行层的取消路径处理。

### 取消与资源释放

调用方中断（用户取消、宿主断开）时的要求与
[会话清理](../architecture/session_and_lease.md)一致：

- 正在等待的动作被拒绝
- **所有按住状态被释放**：鼠标按键、修饰键、拖拽
- 指示层不残留

最后一条影响面最大：一次中断把系统留在"鼠标按键按下"的状态，
会让用户完全失去对鼠标的控制。

## 运行时状态与重置

### 什么会被重置

`js_reset` 丢弃：

- 全部变量与函数绑定
- 全部目标句柄
- 全部剪贴板句柄

**但不会丢弃**（见[会话与控制租约](../architecture/session_and_lease.md)）：

- 目标绑定关系
- 会话级审批授权
- 持久级审批授权

即：重置的是**运行时的 JavaScript 环境**，不是会话本身。

### 超时后的可疑状态

`js` 超时后，运行时可能停在一个不确定的位置：某个 Promise 悬空、
某个循环还在跑、某个动作已投递但结果未知。

**此时不应继续使用该运行时。** 超时返回时应当明确建议调用方执行 `js_reset`。

实现上，超时后运行时被标记为不可用，后续 `js` 调用直接拒绝，
直到执行 `js_reset`。这比允许继续使用一个状态未知的环境更安全。

## 版本准入

运行时对象上暴露协议版本，见
[ADR-0012](../decisions/adr_0012_protocol_versioning.md)：

```js
scu.protocolVersion;   // 单调递增的整数
```

调用一个当前版本不存在的 API 时，**返回 `protocol_version_mismatch` 错误**，
而不是 `undefined`。

实现方式是在运行时对象外层加代理：未定义的属性返回一个函数，
调用时抛出该错误。这样调用方能在正确的层面归因，
而不是收到一个指向别处的类型错误。

## 未定项

- **超时时长的取值**：需要在"容纳正常动作序列"与"及时回收死循环"之间权衡。
- **输出预算的具体上限**：量级已定（数万 token），精确值待定。
- **定时器的上限**：显式等待需要一个上限，但上限是否与 `js` 调用的超时共用尚未决定。
- **是否允许 `console.log`**：当前设计只有 `scu.write`。是否额外支持 `console.log`
  作为调试通道待定——支持它会引入"调试输出与正式输出混在一起"的问题。
