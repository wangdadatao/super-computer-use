# 元素寻址

元素引用的字符串格式与解析规则。身份的构造算法见
[元素身份](../architecture/element_identity.md)。

## 格式

```
<role>#<fingerprint>
```

示例：

```
AXTextField#7a3f
AXButton#1b20
AXStaticText#9c04
```

- `role`：平台角色名。macOS 上取 AXRole，去掉 `AX` 前缀可选，不强制。
- `fingerprint`：身份指纹的短形式，固定 4 位小写十六进制。

短形式只有 65536 个取值。这是**有意的**：指纹用在人工阅读的元素表里，
过长会破坏可读性。碰撞的处理在匹配阶段——指纹相同但结构路径不同的元素
会被判定为 `ambiguous`，而不是任选一个。

## 元素表行格式

```
[<ref>] "<title>" <attributes...>
```

属性按固定顺序输出，缺省则省略：

| 属性 | 输出形式 | 出现条件 |
| --- | --- | --- |
| value | `value="..."` | 元素有值且非空 |
| 次要动作 | `actions=[a,b]` | 元素声明了点击之外的动作 |
| 状态 | `state=focused,selected` | 元素有非默认状态 |

示例：

```
[AXWindow#3f01] "网易云音乐"
  [AXTextField#7a3f] "搜索" value="" actions=[press]
  [AXButton#1b20] "搜索"
  [AXList#2d77]
    [AXRow#44a1] "周杰伦 - 晴天"
    [AXRow#44a2] "周杰伦 - 七里香"
```

**缩进表示层级。** 每级两空格。这比输出父节点引用更省 token，
且人类可读。

## 解析规则

调用方传入的引用按以下规则解析：

1. 以 `[` 开头的原始行可直接切片使用，无需解析结构。
2. 引用必须在当前快照内存在，否则按[失效模型](../domains/staleness_model.md)处理。
3. 引用与坐标不可同时出现。同时给出时拒绝执行，不做优先级推断。

## 未定项

- 指纹长度为 4 位是当前设计。若实测碰撞率过高，考虑扩展到 6 位，
  或对相同指纹的元素加序号后缀。
- 是否需要支持"按属性查询"（例如 `AXButton[title="搜索"]`）作为
  引用失效后的补充寻址手段，待定。当前设计只提供显式引用，
  避免引入第二套寻址语义。
