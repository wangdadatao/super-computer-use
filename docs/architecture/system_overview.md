## 分层

SCU 分为四层，依赖方向单向向下。

```
┌─────────────────────────────────────────────────────┐
│  接入层  Agent surface                              │
│  MCP stdio 服务；对 agent 暴露 code mode（写代码）   │
└────────────────────────┬────────────────────────────┘
                         │ 动作请求
┌────────────────────────┴────────────────────────────┐
│  策略层  Policy                                      │
│  允许 / 需确认 / 拒绝；拒绝类目；审批状态与作用域     │
└────────────────────────┬────────────────────────────┘
                         │ 已允许的动作
┌────────────────────────┴────────────────────────────┐
│  协议层  Session & protocol                          │
│  快照管理 · 元素身份 · 令牌签发与失效 · 收敛与效果回报│
└────────────────────────┬────────────────────────────┘
                         │ 平台无关的目标操作原语
┌────────────────────────┴────────────────────────────┐
│  原生层  Platform backend                            │
│  AX 树与变更通知 · 事件注入 · 屏幕捕获 · 权限检测     │
│  自建窗口登记（供排除）                              │
└─────────────────────────────────────────────────────┘
```

> **P0 实际**（上图是设计目标，下列差异是已知的，不是遗漏）：
> 接入层是普通 MCP 工具（`get_ax_state` 等，加 `--actions` 才有 `click`），不是 code mode；
> `MCPServer` 持有一个 `DesktopSession`（令牌与快照），所以接入层**不是**无状态的；
> 策略层只有 `PolicyGate` 的拒绝类目，没有「需确认」与审批；
> 协议层有令牌签发与失效、按路径定位句柄、轮询式收敛与效果摘要，没有元素身份注册表；
> 原生层有 AX 读树、权限检测、`AXPress`、输入/设值与窗口截图；没有变更通知、事件注入与窗口登记表。

**接入层**只负责把 agent 的请求翻译成动作请求。它不持有状态，
不含平台判断，可以整体替换（MCP、CLI 或直接库调用）。

**策略层**决定一个动作是否允许执行。它不持有快照状态，
因此可以在协议层之前判定——被拒绝的动作不会消耗令牌。
详见[策略与审批](policy_layer.md)。

**协议层**是 SCU 的核心价值所在。所有与"可靠性"相关的机制都在这一层：
它决定一个元素引用是否仍然有效、一次动作是否真的生效、
以及什么时候必须让调用方重新读取状态。这一层不直接调用任何操作系统 API，
也不做策略判断。

**原生层**是薄封装，把平台 API 归一化成协议层需要的原语。它不做决策，
不判断元素是否"看起来一样"，只忠实返回平台给的事实。

它是唯一直接触碰操作系统的层，并额外持有一个小范围状态：
**SCU 自建窗口的登记表**。这个状态的存在理由是把自身产生的窗口
排除出截图与元素表，详见[虚拟指示层](virtual_indicator.md)。

## 进程边界与通信

帧格式与消息目录见[原生层线协议](../interfaces/native_wire_protocol.md)。

协议层运行在服务进程内，原生层以**独立 sidecar 进程**形式存在。

```
Agent 进程
    │  stdio (MCP)
    ▼
SCU 服务进程（接入层 + 策略层 + 协议层）
    │  Unix domain socket，长度前缀 JSON 帧
    │  连接建立时交换协议版本，必须完全相等
    ▼
SCU 原生进程（原生层）
    │
    ▼
macOS（AXUIElement / CGEvent / ScreenCaptureKit）
```

分成两个进程的理由：

- **权限隔离**：macOS 的辅助功能与屏幕录制权限授予单个可执行文件。
  只有原生进程需要这两项权限，服务进程不需要。
- **崩溃隔离**：原生 API 调用（尤其是跨进程的 AX 调用）可能挂起或崩溃，
  不应连带杀死持有会话状态的服务进程。
- **替换成本**：移植到 Linux 时只需替换原生进程，其余三层不变。

跨进程边界的版本协商规则见
[ADR-0012](../decisions/adr_0012_protocol_versioning.md)。

## 跨平台抽象

协议层面向一个平台无关的**目标（Target）**接口工作。目标有两类实现：

- **应用目标（app target）**：一个正在运行的桌面应用的一个窗口
- **页面目标（tab target）**：一个浏览器标签页

两者共享同一套操作面，这样"点击编号 42"这个语义对应用和网页是同构的，
agent 不需要为两者写不同的代码路径。

平台差异被隔离在原生层。已知的差异点（待实现时验证）：

| 能力 | macOS | Linux (AT-SPI2) |
| --- | --- | --- |
| 无障碍树 | AXUIElement | AT-SPI2 |
| 树变更通知 | AXObserver | AT-SPI2 事件 |
| 事件注入 | CGEvent | XTest / libinput |
| 屏幕捕获 | ScreenCaptureKit | PipeWire / X11 |
| 捕获时排除窗口 | 支持 | 合成器支持程度不一，见 ADR-0007 风险 |
| 元素稳定标识字段 | AXIdentifier（可能缺失） | 取决于工具包 |

具体平台映射不在本文展开，见[决策：macOS 优先](../decisions/adr_0005_macos_first_linux_later.md)。

<a id="responsibility_boundary"></a>
## 职责边界

明确划线，避免职责渗漏：

| 层 | 负责 | **不**负责 |
| --- | --- | --- |
| 接入层 | 翻译请求、序列化响应 | 状态管理、策略判断、平台判断 |
| 策略层 | 动作准入、审批状态 | 快照状态、动作内容改写、平台判断 |
| 协议层 | 快照与身份、令牌有效性、收敛与效果核对 | 调用系统 API、决定用户意图、动作准入 |
| 原生层 | 读取平台事实、注入事件、维护自建窗口登记 | 判断元素"是否还是同一个"、缓存跨调用状态 |

**两个"不做"值得单独强调：**

- 协议层不做策略判断。它不会因为某个应用看起来危险就拒绝——
  那是策略层的职责。
- 策略层不改写动作。它要么放行原动作，要么拒绝，不做替换或降级。

## 用户可见的一面

SCU 在屏幕上留下可见痕迹，这是 AX 优先寻址的必要补偿：

- **虚拟指示层**：操作点与目标窗口的可见标记，见[虚拟指示层](virtual_indicator.md)
- **审批提示**：需要确认的动作会呈现给用户，见[策略与审批](policy_layer.md)

两者的共同约束是：**不进入 SCU 自己的读取路径。**
指示层不能出现在截图或元素表里；审批提示同理，
否则模型会看到自己引发的界面变化并把它们当作任务状态的一部分。

## 尚未确定的部分

- **并行执行**：当前设计假设一次只驱动一个目标，见
  [会话与控制租约](session_and_lease.md)的串行化一节。
  是否允许多会话并行尚未决策。
- **服务进程的生命周期**：常驻、按需启动，还是随 agent 会话启停。
- **收敛判定的具体阈值**：P0 已取启发式初值（200 毫秒轮询、连续两次一致、3 秒上限），
  是否合适仍待验证，已知会错过两秒后的变化，见[动作收敛与等待](action_convergence.md#p0_implementation)。
- **画布尺寸**：见 [ADR-0008](../decisions/adr_0008_coordinate_canvas.md)。
