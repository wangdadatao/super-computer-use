# 元素身份

本文描述 SCU 如何在无障碍树变化后仍然识别出"同一个元素"。这是 SCU 相对
既有实现的核心差异点。不覆盖快照与令牌的状态迁移
（见[快照生命周期](snapshot_lifecycle.md)），设计理由见
[ADR-0004](../decisions/adr_0004_stable_element_identity.md)。

## 问题

既有实现用**位置**寻址元素：读一次无障碍树，给每个元素分配一个序号，
后续动作引用这个序号。

```
[42] AXTextField "搜索"
```

序号只在产生它的那一次读取中有效。任何界面变化——列表刷新、弹窗打开、
一个元素被插入到前面——都会让序号整体错位。调用方必须每次动作后重新读取，
而且必须先知道自己手上的引用已经失效。

问题在于**失效是静默的**：序号 42 仍然存在，只是指向了别的控件。

## 身份指纹

SCU 改用**基于内容**的元素身份。每个元素计算一个指纹，指纹由平台提供的
稳定字段组合而成：

| 字段 | 来源 | 稳定性 |
| --- | --- | --- |
| role | AXRole | 高——同一控件类型内不变 |
| subrole | AXSubrole | 高 |
| identifier | AXIdentifier | **最高，但常缺失**——应用可显式设置 |
| title / description | AXTitle、AXDescription | 中——文案可能变化 |
| 结构路径 | 父链 role 序列 + 同级序号 | 中——插入元素会改变 |

指纹 = `hash(identifier, role, subrole, title, structural_path)`

设计意图：**高质量字段存在时以它为主，缺失时退化为结构信息。**
应用显式设置了 `AXIdentifier` 的元素（多数原生控件的搜索框、工具栏按钮会设）
指纹最稳定；完全没有任何标识的自绘控件只能依赖结构路径，稳定性最差。

指纹的短形式作为对外的元素 ID，见[元素寻址](../interfaces/element_addressing.md)。

## 匹配算法

给定一个指纹和一个新快照，返回匹配结果：

1. **精确匹配**：新快照中存在指纹完全相同的元素 → 直接命中。
2. **强匹配**：`identifier` 相同，其他字段有变化 → 命中，标记为"已变化"。
   这覆盖了"同一个控件文案变了"的情况。
3. **结构匹配**：`identifier` 缺失时，用 role + 父链 + 同级序号定位，
   并校验 title 相似度。命中则标记为"结构推断"。
4. **未命中**：以上都失败 → 报告元素已消失，由调用方决定后续。

**算法不猜测。** 当第 3 步出现多个同等候选时，返回歧义而不是任选一个。
一次错误的"猜对了"比一次明确的失败代价更高，因为它会让调用方以为动作生效了。

## 匹配结果

匹配返回四态，而不是布尔值：

| 状态 | 含义 | 调用方可做 |
| --- | --- | --- |
| `stable` | 指纹完全一致 | 直接使用，无需重新解析 |
| `changed` | 身份一致，属性有变化 | 使用，并可感知变化 |
| `inferred` | 靠结构推断命中 | 使用，但建议动作后核对效果 |
| `missing` | 未找到 | 重新读取状态，或向用户求助 |
| `ambiguous` | 多个候选 | 必须重新读取状态 |

`inferred` 和 `ambiguous` 的区分是刻意的：前者是"大概率对"，后者是"无法判断"。

## 与快照的关系

元素身份**不能单独使用**，它必须与快照版本绑定：

- 快照未变（令牌有效）→ 指纹无需重算，直接按位置访问
- 快照已变（令牌失效）→ 用指纹在新快照中重新匹配

这样在界面稳定时零成本，界面变化时仍有恢复能力。两者的配合见
[快照生命周期](snapshot_lifecycle.md)。

## 已知限制

- **列表型界面**：表格和列表里的行如果用相同 role 且无 identifier，
  同级序号会随排序变化。这类元素只能靠 title 区分，容易歧义。
- **动态内容**：时间戳、进度百分比这类频繁变化的 title 会持续污染指纹。
  需要考虑把易变字段从指纹中排除——具体排除规则待实现时定。
- **虚拟化列表**：只渲染可见行的列表（常见于 Electron 应用）会让
  未显示的元素根本无法寻址。

以上限制是设计上的已知缺口，不打算在首版解决。

## 待验证项

指纹方案建立在"真实应用的无障碍树提供足够稳定字段"这一假设上，
**该假设尚未验证**。验证方法：

1. 对若干真实应用（至少包含一个原生应用和一个 Electron 应用）导出无障碍树。
2. 在界面发生受控变化（刷新列表、打开弹窗、切换标签页）前后各导一次。
3. 检查设计中的指纹字段在变化前后的稳定性。

若原生应用普遍不提供 `AXIdentifier`，指纹的稳定性会显著下降，
届时需要回到本设计重新评估。
