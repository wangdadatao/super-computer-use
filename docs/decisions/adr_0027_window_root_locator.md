# ADR-0027 窗口列表与窗口根定位

- **状态**：已接受（实验性）
- **日期**：2026-10-20

<a id="window_root_locator"></a>

## 背景

ADR-0026 做了显式窗口选择，但只绑定了截图与坐标动作：元素表仍读取整个应用，
`click` / `type_text` / `press_key` / `set_value` 仍以应用根定位。这个“半绑定”有两个问题：

1. 调用方无法先知道有哪些窗口，只能猜标题；
2. 用窗口 A 的令牌点到了窗口 B 的同名元素，动作仍会执行，显式选择没有贯穿元素动作。

## 决策

### 1. 增加只读的 `list_windows`

```json
{"pid": 42}
```

返回 `windows: [{title?, frame?}]`，只枚举应用声明的 AX 窗口，不激活、不截图、不排序。
这是只读工具，与 `list_apps` 一样不改变桌面状态。

- 标题可能缺失（`nil`），frame 以全局屏幕点为单位，副屏可为负；
- 同名窗口会全部列出；后续按标题选择时仍只取第一个精确匹配；
- 空数组表示平台没有可枚举的 AX 窗口，不是错误。

### 2. `get_ax_state(window:)` 以窗口为根读树

传 `window` 时，`dumpTree` 从匹配的 AX 窗口子树开始遍历：

- 返回树的根是 `AXWindow`，不是 `AXApplication`；
- 句柄路径、标签、元素表都相对于这个窗口；
- 截图与坐标动作仍绑定同一个标题；
- 找不到标题返回 `window_not_found`，**不回退到应用根**。

不传 `window` 时保持原行为：应用根、令牌取默认截图窗口。

### 3. 元素动作使用令牌上的窗口标题

`performAction` / `typeText` / `pressKey` / `setValue` 增加可选 `windowTitle`。
协议层从令牌记录中取出标题并随动作发送；原生层用同一个 `windowElement` 解析根。
这样窗口 A 的句柄不会解析到窗口 B：

- 标题还在：路径相对窗口 A，正常核对与执行；
- 标题已改：动作开始前返回 `window_not_found`，不执行；
- 没有 `windowTitle`：仍以应用根定位，语义不变。

### 4. 版本升到 v11

新增请求与应答，且 `dumpTree` / 四个元素动作的请求形状变化。旧客户端与新原生层不能混用。

## 取舍

**接受标题仍是唯一标识。** 没有稳定的公开窗口 ID；标题会变、可能重复。
好处是调用方可以直接从 `list_windows` 读到可读的标题；代价是改名后必须重新读取。
同名窗口只选第一个，是已知限制。

**接受根切换带来的路径语义变化。** 同一个应用，带窗口和不带窗口得到的句柄路径不同，
令牌不能跨根复用。这是有意的：句柄只在签发它的快照里有效。

**没有做窗口级应用授权。** 授权粒度仍是应用（ADR-0024），`list_windows` 与应用读取走同一检查。

**没有做跨窗口批量操作。** 一个令牌只对应一个根；多窗口任务需要多次读取。

## 后果

- 线协议 v11：新增 `listWindows` / `windows`，`windowTitle` 进入 `dumpTree` 与元素动作；
- MCP 增加只读工具 `list_windows`；`get_ax_state(window)` 的文档从“只影响截图”改为“元素表也以窗口为根”；
- 令牌记录、元素动作与事后重读都携带窗口标题；
- 已知限制：同名窗口只选第一个；标题变化使旧令牌失效；没有窗口 ID、没有多窗口真实回归。
