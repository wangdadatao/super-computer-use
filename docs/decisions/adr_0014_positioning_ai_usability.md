# ADR-0014 定位为对 AI 更好用，用可测指标判断，而不是以某个机制为差异点

- **状态**：提议中。定位已由项目负责人确认（2026-10-18）；度量方式与阈值待确认，阈值**尚未设定**
- **日期**：2026-10-18

## 外部观察来源

本文涉及对两套已发布实现的观察结论。来源、具体证据与复核方法见
[verification/external-sources.md](../../verification/external-sources.md)。
**这些观察来自对程序工件的分析，不是使用体验的度量**：本文没有任何关于两者实际表现好坏的数据。

## 背景

项目负责人明确了定位：**做一个对 AI 而言比 Codex Computer Use 与 Grok Computer Use 都好用的工具，
结合两者所长。** 好用的评判者是 AI，不是人。

此前的文档把差异点写成**稳定元素身份**：[README](../../README.md) 的设计出发点、
[ADR-0004](adr_0004_stable_element_identity.md)、[ADR-0013](adr_0013_p0_vertical_slice.md)
的"门槛失败时的处理"都是这样表述的，并预写了"身份失败就重新评估项目定位"。
基线数据对身份方案不利（访达窗口内可交互元素 93.0% 落入 K4，见
[基线记录](../../verification/2026-10-16-baseline-identity.md)），
在那种表述下，这等于项目存疑。

但目标是"综合更好用"，身份只是达成它的**一种手段**。把手段当成存在理由，
会让一个机制的验证结果错误地决定项目的去留。

另一个问题是**没有尺子**。现有的出口门槛（K4 比例、令牌用例、清理）全是机制层面的，
没有任何一项能回答"AI 用 SCU 是否比用另外两个更好"。

## 决策

### 1. 定位

目标是**对 AI 使用体验优于 Codex 与 Grok 的桌面操作工具**。达成方式有两条：

- 采纳两者已被观察到的长处（见下表）；
- 补两者都缺的（目前观察到的是**动作效果回报**：两者的动作接口都不返回效果摘要）。

元素身份、收敛判定、令牌等机制是**手段**。它们按对"好用"的贡献取舍，
不再作为项目存在的理由。

### 2. "好用"的度量维度

以 AI 的视角，分五个维度。**这是候选维度，不是已验证的完备清单**：

| 维度 | 含义 | 采集方式 | 现状 |
| --- | --- | --- | --- |
| 任务成功率 | 固定任务集上完成任务的比例 | 固定任务集，同一模型 | **没有任务集** |
| 调用效率 | 完成任务所需的工具调用次数 | 同上 | 没有任务集 |
| 状态读取成本 | 一次状态读取的输出体积与耗时 | 对 `get_ax_state` 的输出与计时 | 耗时有记录（[读树耗时](../../verification/2026-10-17-read-latency.md)）；输出体积未记录 |
| 动作可信度 | 误操作数：动作落到错误目标，或静默失败 | 任务运行日志 | 没有动作 |
| 失败可恢复性 | 失败后 AI 能否依据返回内容走到正确的下一步 | 失败注入用例 | 没有 |

### 3. 度量分两层，且"优于"在对照可行前不得声称

- **绝对基线**：SCU 自己在任务集上的各项数值，随版本记录。先做。
- **与 Codex、Grok 对照**：需要在同一任务集上驱动对方的工具。**这是否可行没有调查过**，待验证。
  对照可行之前，文档、README 与对外表述**不得声称"优于"**，只能陈述绝对数值。

**阈值在首次采样前冻结**，与 [ADR-0013 的出口门槛](adr_0013_p0_vertical_slice.md#出口门槛)同一规则：
采样后再定阈值，容易把标准调到刚好通过。现在**没有设定任何阈值**，
任务集与阈值是后续工作，设定时在本文追加记录。

### 4. 采纳清单

来源与证据见 [external-sources.md](../../verification/external-sources.md)。

| 长处 | 来源 | 采纳状态 | 落点 |
| --- | --- | --- | --- |
| 无障碍树优先、文本元素表 | 两者 | **已采纳** | 已实现（只读） |
| 动作后自动等待（约 1 秒，有加载指示时最多再加 5 秒） | Codex | 采纳，先做最小版 | [ADR-0011](adr_0011_convergence_over_fixed_delay.md)，P0 动作档 |
| 快照令牌 | Grok | 采纳 | [ADR-0003](adr_0003_snapshot_token_contract.md)，P0 |
| 结构化拒绝，带升级建议（`code`、`message`、`escalation`） | Grok | 采纳；`escalation` 字段是否需要待定 | [错误与拒绝](../interfaces/error_taxonomy.md) |
| 应用拒绝清单与三态决策 | Grok | 采纳最小版（终端类、SCU 自身） | [ADR-0009](adr_0009_policy_layer.md) |
| 变更通知驱动的失效检测 | Codex | **待验证**；P0 先用动作时比对 | [快照生命周期](../architecture/snapshot_lifecycle.md) |
| 少量工具（code mode，`js`） | Codex | 待定，顺序后置 | [ADR-0002](adr_0002_code_mode_surface.md) |
| 显式等待原语 | Grok | 暂不；设计保留 | v1 范围的"设计保留"一行 |
| 固定逻辑画布的坐标 | Grok | 暂不，随坐标动作 | [ADR-0008](adr_0008_coordinate_canvas.md) |
| 控制租约 | Grok | 暂不 | [会话与控制租约](../architecture/session_and_lease.md) |
| 虚拟光标 / 光标覆盖层 | 两者 | 暂不 | [ADR-0007](adr_0007_virtual_indicator_layer.md) |
| 按应用注入知识 | Codex | 暂不 | [应用知识](../architecture/app_knowledge.md) |
| **动作效果摘要** | 两者都缺 | **补缺，P0 内做** | [ADR-0006](adr_0006_action_effect_verification.md) |

`get_ax_state` 的层级优先显示与 `focus` 展开是针对真实使用中遇到的问题做的。
两者是否有类似机制**没有调查**，因此不声称它们是新的。

### 5. 对 ADR-0013 的影响

- **元素身份验证的结论不再决定项目去留。** 它只决定是否实现句柄注册表
  （决策规则已在 ADR-0013 的"暂缓句柄注册表"一节）。
- **"重新评估项目定位"的触发条件改为基于上述度量**，不再基于 K4 比例。
  具体条件**待阈值冻结时一并写定**；在此之前，没有任何已定的"项目失败"判据。
- ADR-0013 的出口门槛里与注册表暂缓、P0 范围不一致的几项，在该文追加记录处理。

## 取舍

**放弃了"身份是核心差异点"的叙事。** 好处是项目不被单一机制的验证结果绑架；
代价是定位变宽，更难证伪。"更好用"是个宽目标，**没有冻结的阈值就永远不会失败**，
所以第 3 条要求先冻结阈值再采样。

**对照实验可能做不成。** 如果没法驱动 Codex、Grok 的工具，就只能做自我基线，
不能声称优于对方。接受这一点，也不为了能声称"优于"而降低对照的严格性。

**接受了采纳清单是基于工件观察的。** 表里"长处"的判断来自工件分析，
没有经过使用验证；某一项被证明在实际中并不好用时，应当从清单中移除，而不是坚持采纳。

## 后果

- README 增加定位表述；"设计出发点"保留，但差异点不再等同于元素身份
- ADR-0013 追加记录：句柄门槛、坐标令牌用例、清理门槛、重新评估条件
- 需要设计一套任务集与采集方式（后续工作，设计时在本文追加记录）
- 效果摘要成为 P0 内要做的功能；是否列为出口门槛待定，见 ADR-0013 的追加记录
