# ADR-0004 用内容寻址取代位置寻址

- **状态**：已接受，可行性待验证
- **日期**：2026-10-16

## 背景

既有实现都用**位置**寻址元素：读取一次无障碍树，为每个元素分配一个序号，
后续动作引用这个序号。观察到的两套实现都属此类，只是字段名不同
（一处用元素下标，一处用元素 id），语义相同——**序号只在产生它的那次读取中有效**。

配合 [ADR-0003](adr_0003_snapshot_token_contract.md) 的令牌机制，
失效被检测得很好：调用方不会把动作投递到错位的元素上。

但**恢复能力是缺失的**。令牌失效后调用方唯一的选择是重新读取整棵树、
重新定位目标。对于"界面刷新了一下，但我要操作的元素还在"这种最常见的情况，
代价是完整重读一次。

这带来两个后果：

- **成本**：每次界面微变都要重读整树
- **精度**：重读后模型需要凭文本重新定位目标，可能定位到相邻的相似元素
  （例如同名的两行、并列的两个按钮）

## 决策

**SCU 用基于内容的指纹取代位置序号作为元素身份。**

指纹由平台提供的稳定字段组合而成：角色、显式标识符、标题、
以及结构路径。指纹在界面变化前后保持不变，元素引用因此可以跨快照使用。

具体地：

- 元素引用编码为 `<role>#<fingerprint>`，不含位置信息
- 令牌有效时按位置快速访问（指纹不需要重算）
- 令牌失效时用指纹在新快照中重新匹配，返回五态结果
  （`stable` / `changed` / `inferred` / `missing` / `ambiguous`）
- 多个同等候选时返回歧义，不任选一个

## 取舍

**放弃了简单性。** 位置序号是一个整数，指纹是一套需要维护的算法：
字段选择、易变字段的排除、结构路径的计算、碰撞处理。
这是 SCU 相对既有实现增加的主要复杂度。

**接受了匹配可能出错。** 指纹算法在缺少显式标识符时会退化到结构推断，
结构推断在列表型界面下不可靠。设计上的应对是显式区分
`inferred` 与 `ambiguous`，让调用方知道当前匹配的可信度，
而不是把所有匹配都当作确定结果。

**放弃了短引用。** 4 位十六进制指纹只有 65536 个取值，
在大型界面里碰撞是可能的。选择短形式是为了元素表的可读性，
碰撞在匹配阶段处理。

## 后果

- [元素身份](../architecture/element_identity.md)成为架构层的核心组件
- 元素引用的格式不再是一次性的，调用方可以持有并在后续快照中复用
- 需要真实的无障碍树样本来验证字段选择的正确性

## 风险

**本决策的核心假设尚未验证**：真实应用的无障碍树是否提供足够稳定的字段。

若原生应用普遍不设置显式标识符，指纹将主要依赖结构路径，
而结构路径的稳定性显著低于标识符。届时指纹的相对优势会缩小到
"能感知到元素移动了"，而不是"能找回元素"。

验证方法记录在[测试策略](../operations/testing.md)，
需要授予辅助功能权限并采集真实样本。
