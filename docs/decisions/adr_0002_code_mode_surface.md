# ADR-0002 用 code mode 作为 agent 接口

- **状态**：已接受
- **日期**：2026-10-16

## 外部观察来源

本文涉及对两套已发布实现的观察结论。来源、具体证据与复核方法见
[verification/external-sources.md](../../verification/external-sources.md)。

## 背景

把能力暴露给 agent 有两种形态：

**平铺工具**：每个能力一个工具，模型调用工具并传 JSON 参数。
观察到的 Grok Bot Computer Use 采用这种形态，暴露了十余个工具
（截图、点击、移动、拖拽、输入、按键、滚动、等待、权限检查、
列应用、解析应用、读状态、设值、次要动作）。

**code mode**：只暴露一个代码执行入口，能力通过运行时库提供。
观察到的 Codex Computer Use 采用这种形态，主工具面收敛到三个
（执行、重置、回合结束通知），全部能力经 JavaScript API 调用。

## 决策

**SCU 采用 code mode。**

- 主工具面是一个 JavaScript 执行入口，加上一个重置入口
- 全部能力通过注入运行时的 `scu` 对象提供
- 元素表以文本返回，模型在代码里解析和筛选，而不是由服务端预加工

## 取舍

**放弃了调用轨迹的可见性。** 平铺工具下，每一次点击、每一次读取都是
独立的可观测事件，易于审计和回放。code mode 下，一次 `js` 调用内部
可能完成十几步操作，外部只看到一次调用。这对调试和合规审计都是损失。

**放弃了参数校验的严格性。** 工具的参数 schema 由协议层强校验；
JavaScript 调用只能靠运行时类型检查，错误发现更晚。

**换来的收益**：

- **上下文成本**：十余个工具的定义本身占用可观的固定开销，
  且随能力增长线性上升。code mode 的工具面不随能力增长。
- **组合能力**：模型可以在一次调用里循环、过滤、条件判断，
  而不是通过多轮工具调用往返。例如"遍历列表找到标题匹配的那一行"，
  在平铺工具下需要读取整表再由模型自己匹配；在 code mode 下是几行代码。
- **状态复用**：运行时是持久的，模型可以在多次调用间保留中间结果。

## 后果

- 接入层必须提供一个安全的 JavaScript 执行沙箱
- 工具描述需要把能力说清楚，否则模型不知道有哪些 API 可用；
  这比平铺工具的 schema 更依赖提示词质量
- 需要提供运行时重置入口，否则模型可能积累不可预期的状态
- 审计场景下需要额外的调用内追踪，不能只依赖工具调用日志

## 追加记录（2026-10-19，v1 采用平铺工具）

v1 用平铺 MCP 工具（`click` / `type_text` / `press_key` / `set_value` 等）交付，
**没有引入本 ADR 的 code mode 运行时**。理由与范围见
[ADR-0013 的 v1 收口记录](adr_0013_p0_vertical_slice.md#v1_close_2026_10_19)：
平铺工具已满足最小工具面，code mode 需要 JS 沙箱与运行时设计，后置到 v2。本 ADR 的方向不变。

## 追加记录（2026-10-19，v2 接口演进计划）

v1 用平铺工具交付（见 [ADR-0013 的 v1 收口](adr_0013_p0_vertical_slice.md#v1_close_2026_10_19)）。
**平铺是逐动作审计与策略门禁的取舍，不是临时方案**；它不会自动阻止编排层的演进。

v2 的能力面会扩大（截图、坐标、滚动、拖拽、启动应用、窗口），平铺工具会从 7 个涨到十几个，
语义开始重叠。接口按以下顺序演进，**不把完整 JS 运行时作为 v2 的前置条件**：

1. **动作仍平铺。** `click` / `type_text` / `press_key` / `set_value` 与未来的坐标动作保持独立工具：
   每个动作过一次策略门禁、返回效果摘要、可被单独批准与审计。
2. **先加 `batch`。** 接受一个动作序列，服务端逐步执行：每步仍走策略/令牌/核对；
   遇到 `stale_snapshot` 或策略拒绝就停，返回已完成步骤与失败步骤。
   它把"读 → 点 → 重读 → 输入"压成一次往返，同时保留逐动作的可审计性。
3. **受限 code mode 作为后续选项。** 只在度量证明平铺 + `batch` 不够时才引入：
   只暴露 `getState / act / wait / log`，沙箱、超时、动作次数上限，每个动作仍过策略门禁。
4. **触发条件用 [ADR-0014](adr_0014_positioning_ai_usability.md) 的指标。**
   在固定任务集上量调用次数、状态读取成本与 token，与平铺基线比较；没有数据不引入新接口。

本 ADR 的方向（少量工具 + 代码化编排）不变，只是把步骤拆成"平铺 → batch → 受限 code mode"。
