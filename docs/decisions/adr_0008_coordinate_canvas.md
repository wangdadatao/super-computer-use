# ADR-0008 坐标使用固定逻辑画布

- **状态**：已接受
- **日期**：2026-10-16

## 背景

[ADR-0001](adr_0001_accessibility_first.md) 保留了视觉坐标作为兜底路径。
一旦涉及坐标，就必须回答"这个坐标相对于什么"。

可选的基准有多种，各有问题：

- **屏幕绝对坐标**：目标窗口移动或显示器布局变化后立即失效，且多显示器下坐标系不统一
- **窗口内相对坐标**：窗口内部滚动、缩放后语义改变
- **物理像素**：随显示器 DPI 变化，同一逻辑位置在不同屏幕上数值不同

参考实现中观察到一种做法：**固定尺寸的逻辑画布**。
被分析的其中一套实现明确将坐标定义为"固定 1280×800 画布上的像素，
原点在左上角"，并把这个画布与截图绑定为同一个令牌作用域。

## 决策

**SCU 的坐标一律相对于固定的逻辑画布。**

- 画布尺寸固定，原点在左上角，x 向右、y 向下
- 坐标令牌绑定的是**画布与目标窗口之间的映射**，而不是画布自身
- 返回截图时按画布尺寸归一化，而不是返回原始像素
- 用户可见的坐标值始终在画布范围内

画布的具体尺寸待实现时确定，倾向 1280×800 量级：
足以容纳常见窗口的细节，又不至于让单张截图过大。

### 两种执行模式下的画布映射

画布的映射目标随[执行模式](../domains/glossary.md)变化：

| 模式 | 画布映射到 | 说明 |
| --- | --- | --- |
| 后台操作 | 绑定的目标窗口 | 坐标相对该窗口的截图 |
| 接管显示 | **主显示器** | 作用范围是整个显示，没有目标窗口 |

**接管模式只覆盖主显示器，不覆盖整个虚拟桌面。** 多显示器时，
其他显示器上的内容不在画布内，无法通过坐标操作。

这个限制是刻意的：跨显示器的坐标映射需要处理显示器之间的相对位置、
不同 DPI、以及混合分辨率，而收益仅是"能操作副屏上的东西"。
首版接受这个限制，并在接管模式启用时**明确告知调用方当前画布对应哪一块屏幕**。

## 取舍

**放弃了像素级精确。** 归一化到固定画布意味着小于一个画布像素的
界面元素在坐标路径下无法精确定位。对这类元素只能走元素寻址。

**接受了缩放带来的误差。** 目标窗口的宽高比与画布不一致时，
需要决定填充还是拉伸策略。拉伸会引入形变，填充会引入坐标偏移的计算。
这是一个实现细节，但会影响坐标精度。

**换来的收益**：

- 坐标语义与显示器配置解耦，同一段操作在不同机器上含义一致
- 截图尺寸可预测，便于估算成本
- 坐标令牌的失效条件简化：只有窗口几何变化才需要失效，
  显示器切换如果改变了窗口几何，会被同一条规则覆盖

## 后果

- 截图管线需要做归一化，不可直接透传原始像素
- 坐标令牌的失效判定依赖窗口几何，需要可靠的几何监听
- 元素寻址与坐标寻址的精度差异变大，
  [ADR-0001](adr_0001_accessibility_first.md) 中"优先元素寻址"的倾向因此更强
- 需要在文档中明确：坐标是画布坐标，不是屏幕坐标，两者不可混用
