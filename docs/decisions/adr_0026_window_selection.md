# ADR-0026 窗口选择：绑定截图与坐标动作

- **状态**：已接受（实验性；窗口根由 [ADR-0027](adr_0027_window_root_locator.md) 补齐）
- **日期**：2026-10-20

<a id="window_selection"></a>

## 背景

ADR-0025 解决了“截图和激活可能不是同一个窗口”，但仍只能选默认（面积最大）窗口。
多窗口应用里，调用方需要明确操作某个窗口，而不是猜哪个最大。

完整方案会让 `dumpTree` 从窗口子树开始，所有动作定位器也以窗口为根，
协议和定位器语义都要改。当前先做一个较小的切片：**显式选择用于截图与坐标动作的窗口**，
元素表仍读取整个应用。

## 决策

### 1. `get_ax_state` 增加可选 `window`

```json
{"pid": 42, "window": "收件箱 - 邮件"}
```

- `window` 是精确标题匹配；
- 绑定记录在令牌上；`get_screenshot`、`click_at`、`scroll_at`、`drag` 都使用它；
- 不传时保持原来的默认窗口选择（面积最大的非最小化窗口）；
- 窗口标题找不到时，原生层在截图/坐标动作前返回 `window_not_found`（`after_refresh`）。

### 2. 元素表仍是整个应用

`get_ax_state` 的树不按窗口过滤：句柄、标签、`click` / `type_text` / `press_key` / `set_value`
仍以整个应用为根。这样不需要改定位器协议，也不会破坏跨窗口的 AX 树。

代价是：元素表里可能同时出现多个窗口；`window` 只影响截图与坐标动作，不影响元素动作。
文档必须明确这一点，不能把它说成“只读取这个窗口”。

### 3. 截图标签按绑定窗口裁剪

截图绑定窗口标题；叠加标签时只保留与该窗口 frame 相交的标签，避免把其他窗口的
`[a]` 画到当前截图上。

### 4. 精确标题匹配，失败不猜

- 同一个应用里多个同名窗口时，选第一个精确匹配；这是已知限制；
- 标题变化（文档改名、页面导航）后旧令牌仍指向旧标题，截图/坐标动作会 `window_not_found`，
  调用方需要重新 `get_ax_state`；
- 没有引入稳定的窗口 ID；AX 窗口编号不是稳定公开契约。

## 取舍

**接受了“半绑定”的不完整。** 现在能明确“截哪个窗口、点哪个窗口”，
但不能“只读这个窗口”。后者需要窗口根定位器，暂不做。

**接受了标题作为标识。** 标题可读、无需额外枚举，但会变化、可能重复。
先用失败的确定性换掉“猜一个窗口”的不确定性。

**没有改变元素动作的窗口语义。** 如果调用方用 `window` 绑定 A，却用标签点了 B 里的元素，
动作仍会执行。这是当前切片的边界；需要严格隔离时应先做窗口根定位器。

## 后果

- 线协议升到 v10：`captureWindow` / `clickAt` / `scrollAt` / `dragAt` 增加可选 `windowTitle`；
- `get_ax_state` 增加 `window` 参数，令牌记录窗口标题；
- 截图元数据已有 `title`，便于确认；
- 新增错误码 `window_not_found`；
- 元素表输出标题行显示 `窗口="…"`；
- 后续：[ADR-0027](adr_0027_window_root_locator.md) 补齐窗口列表与窗口根定位；仍未实现稳定窗口 ID 与多窗口真实回归。
