# ADR-0010 范围限定为 UI 自动化

- **状态**：已接受
- **日期**：2026-10-16

## 外部观察来源

本文涉及对两套已发布实现的观察结论。来源、具体证据与复核方法见
[verification/external-sources.md](../../verification/external-sources.md)。

## 背景

参考实现中，UI 自动化能力之外的边界并不清晰。
其中一套实现把若干领域能力作为**同级的服务**与 UI 自动化并列提供，
包括日历、消息、事件流和历史；另一套则在 UI 自动化之外
提供了消息读取与图片附件获取。

这些能力与 UI 自动化在实现上完全不同：

| 维度 | UI 自动化 | 领域能力 |
| --- | --- | --- |
| 数据来源 | 无障碍树、屏幕像素 | 应用数据库、系统 API |
| 操作方式 | 注入事件、调用无障碍动作 | 直接读写数据 |
| 权限 | 辅助功能、屏幕录制 | 通讯录、日历、完全磁盘访问 |
| 变更风险 | 用户看得见 | 用户看不见（后台改数据库） |
| 平台耦合 | 高（AX / AT-SPI / UIA） | 中（数据库 schema） |

把它们放在同一个服务里会带来两个实际问题：

1. **权限爆炸**：领域能力需要额外的高危权限（如完全磁盘访问以读取消息数据库），
   而 UI 自动化本身只需要辅助功能与屏幕录制
2. **语义混淆**：通过无障碍树操作日历应用，与直接写日历数据库，
   对用户而言是两件不同的事——前者用户看得见并可以打断，后者不能

## 决策

**SCU 的范围限定为 UI 自动化，不提供领域能力。**

明确排除：

- 日历、通讯录、消息等结构化数据的读写
- 系统活动录制与历史查询
- 浏览器扩展的安装与集成
- 音频录制
- 目标应用内部数据的直接访问

**通过 UI 操作日历应用是允许的**——那属于 UI 自动化。
不允许的是绕过界面直接读写数据。

## 取舍

**放弃了"更快更可靠"的路径。** 直接读数据库比解析无障碍树快得多，
也不受界面变化影响。放弃它是刻意的：SCU 要保证的正是
"用户能看见发生了什么"。

**接受了能力面上的劣势。** 用户如果需要一个能读日历的助手，
SCU 单独使用无法满足，需要配合其他工具。

**保留了后续扩展的可能。** 本决策限定的是 SCU 自身的范围，
不排除将来的其他服务以 SCU 为底层 UI 能力。边界在于
不同能力应当是不同服务，而不是同一个服务里的不同端点。

## 后果

- [ADR-0009 策略层独立成层](adr_0009_policy_layer.md)的拒绝类目不需要覆盖领域数据访问，
  因为这类能力根本不存在
- 权限需求收敛为辅助功能与屏幕录制两项，不需要完全磁盘访问等
- 接口面显著变小，[协议总览](../interfaces/protocol_overview.md)的约束范围更清晰
