# ADR-0007 虚拟指示层作为一等可观测面

- **状态**：已接受
- **日期**：2026-10-16

## 背景

[ADR-0001](adr_0001_accessibility_first.md) 确定以无障碍树为主寻址路径，
通过无障碍接口对元素执行动作。

这个选择的直接后果是：**操作过程对用户不可见。** 系统的真实指针不会移动，
界面却在自己变化。在一个正在旁观的用户眼里，应用像是被幽灵操作。

参考实现中观察到一个明确的一致做法：两套被分析的实现都实现了独立的
屏幕指示层，且都在 AX 优先的架构下出现。

| 实现 | 观察到的机制 |
| --- | --- |
| Codex Computer Use | 虚拟光标抽象（协议形式）、两种光标样式（雾状与软件光标）、独立的箭头形覆盖窗口 |
| Grok Bot Computer Use | 光标覆盖层、被控窗口边框覆盖层、接管模式的辉光覆盖层、光标种类枚举 |

两者独立实现同一机制，与 [ADR-0001](adr_0001_accessibility_first.md) 中
"AX 优先"的独立收敛是同一种证据：**它由架构选择推导出来，不是产品偏好。**

同时观察到两处实现都必须处理的第二个问题：指示层是真实窗口，
**会出现在自己的截图里**。两处实现都使用了"捕获时排除指定窗口"的机制，
其中一处还额外设置了窗口的共享类型。

## 决策

**SCU 把虚拟指示层作为一等组件设计，而非可选的界面装饰。**

具体约束：

- 指示层包含操作点指示与目标窗口指示两个元素
- 指示窗口**必须**被排除出 SCU 自身的截图，使用共享类型与显式排除双重防护
- 指示窗口不接收鼠标事件、不夺取焦点、不进入无障碍树
- 指示层的视觉形态随执行模式变化，让用户能区分"后台操作"与"接管显示"
- 指示层可由用户完全关闭

设计细节见[虚拟指示层](../architecture/virtual_indicator.md)。

## 取舍

**接受了原生层的额外复杂度。** 指示层是一个需要维护的窗口：
定位、层级、淡出动画、多显示器处理，以及最麻烦的——捕获排除。
排除机制在跨平台时的可行性未知（Linux 合成器对"捕获时排除窗口"的支持
程度不一）。

**接受了与截图管线的耦合。** 截图路径必须知道指示窗口的存在并将其排除。
这打破了"原生层只忠实返回平台事实"的简洁分层——
原生层现在需要持有"哪些窗口是自己造的"这一状态。

**排除失败的风险是真实的。** 若指示层泄漏进截图，后果不是性能问题而是正确性问题：
模型可能把指示层当作可交互元素。设计中把它列为硬要求而非优化项，正是因为这个后果。

## 后果

- 原生层需要维护自有窗口的注册表，供捕获排除使用
- 截图管线的构造需要携带排除列表
- **引入"执行模式"概念**：系统需要显式区分后台操作与接管显示，
  这个状态同时影响指示层外观、真实指针是否可动、以及用户能否并行使用电脑
- 测试需要覆盖"指示层不出现在截图中"这一断言，属于[测试策略](../operations/testing.md)
  需要新增的用例

## 与既有决策的关系

本决策是 [ADR-0001](adr_0001_accessibility_first.md) 的补充而非替代：
它是 AX 优先选择的必要补偿。若将来放弃 AX 优先改为真实指针控制，
指示层的必要性会大幅下降——但那种情况下 [ADR-0004](adr_0004_stable_element_identity.md)
也随之失去意义。
