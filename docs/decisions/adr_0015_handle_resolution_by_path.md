# ADR-0015 句柄经"路径加核对键"解析，协议层保存快照，原生层保持无状态

- **状态**：已接受（P0 范围）
- **日期**：2026-10-18

## 背景

[ADR-0013](adr_0013_p0_vertical_slice.md) 暂缓了句柄注册表（跨快照延续句柄）。
没有注册表时，动作仍然需要回答一个问题：**调用方给出的句柄，如何回到真实的界面元素？**

句柄是一次读取内的先序编号（见[元素寻址](../interfaces/element_addressing.md#readonly_subset)），
它不是系统对象。动作到达时，界面可能已经变化；此时编号指向的元素可能已经不是当时读到的那个。
[快照生命周期](../architecture/snapshot_lifecycle.md)的原则是**宁可拒绝执行，也不执行到错误的目标上**，
而 P0 采用**动作时比对**（不依赖变更通知，见该文的"驱动来源"一节）。

[系统总览](../architecture/system_overview.md#responsibility_boundary)规定原生层"不缓存跨调用状态""不判断元素是否还是同一个"。
这限制了解法。

## 决策

### 1. 协议层保存快照，句柄翻译成"定位器"

协议层在每次读取时保存整棵树，并为每个句柄计算一个**定位器**：

- **路径**：从应用根节点出发，每一层的一个步骤，含该节点在父节点子列表中的下标、
  **读取时父节点的子节点总数**、该节点的角色；
- **核对键**：目标元素的角色、子角色、标题、标识符、描述。

动作请求携带定位器。原生层沿路径逐层下行，**每一层核对子节点总数与角色**，
到达目标后核对其核对键。任何一项不符，**不执行动作**，返回 `stale` 以及不符的位置与实际读到的事实。
原生层只比较协议层传来的事实，不做"是不是同一个元素"的判断，也不保存任何跨调用状态。

选择"每层核对子节点总数"而不是只核对下标与目标核对键，是因为同级常有标题与角色完全相同的元素
（列表行、重复按钮）。只比目标核对键，在它们之间插入或删除一个元素后，
下标会指向另一个核对键相同的元素，无法发现。逐层核对子节点总数把这类位移变成可检测的失效。

### 2. 读取时必须记录真实子节点数

广度优先读树在预算耗尽时会丢弃尚未读取的子节点（见[读树耗时](../../verification/2026-10-17-read-latency.md)的遍历说明），
因此**快照里的子节点列表可能短于真实子节点数**。`AXNode` 新增 `childCount`：
原生层读取子节点时记录平台返回的真实数量。定位器里的"子节点总数"取自它，不取自快照里的列表长度。

被丢弃的节点只会在其父节点已读取子节点之后的末尾出现，所以已读取的子节点是真实子列表的前缀，
**快照里的下标等于真实下标**。

### 3. 令牌

- 每次读取签发令牌，不透明字符串。会话只保存当前目标的最新快照，并保留最近若干个令牌的状态。
- **读取结果的结构摘要与当前快照相同且目标相同，复用同一个令牌**（句柄编号也因此保持一致）。
  摘要覆盖除位置与大小外的全部字段和子节点数：几何不进摘要，与[快照生命周期](../architecture/snapshot_lifecycle.md)一致。
  这让"界面稳定时令牌不变"成立，而不是每次读取都作废上一次的引用。
- 令牌状态：`current`、`stale`（树变化）、`switched`（目标已切换）。
- 动作时的失效来源有两个：**原生层核对失败**（定位器不符），以及**会话已知失效**（有更新的读取使它失效）。

| 情形 | 错误码 | retry |
| --- | --- | --- |
| 令牌已被更新的、结构不同的读取取代，或原生层核对失败 | `stale_snapshot` | `after_refresh` |
| 令牌属于已被切换走的目标 | `target_switched` | `after_rebind` |
| 令牌未签发，或已被会话丢弃 | `stale_snapshot` | `after_refresh` |
| 句柄在该令牌的快照里不存在 | `element_gone` | `after_refresh` |

令牌未知与令牌失效对调用方的含义相同（重读），所以不另设错误码。
**窗口变化**类别随坐标令牌后置，P0 没有坐标动作。

### 4. 重复使用同一失效令牌

[测试策略](../operations/testing.md)的用例"重复使用同一失效令牌 → 只上报一次失效"有歧义。
本决策的解释：

- **每次使用都被拒绝**，错误码与类别不变——放行一次失效令牌的动作是漏报，不可接受；
- **失效这次状态迁移只记录一次**：令牌从 `current` 到 `stale` 只发生一次，
  会话的失效计数只增加一次，重复使用不再次触发迁移。

可测的可观察量是"拒绝次数等于使用次数，而失效迁移次数为 1"。

### 5. 动作前的会话内先后顺序

策略检查在令牌检查之前（被拒绝的动作不消耗令牌，见[系统总览](../architecture/system_overview.md)），
令牌检查在原生层核对之前（会话已知失效就不必往返原生层）。

## 取舍

**保守，会有误拒。** 逐层核对子节点总数意味着：只要路径上任何一层的子节点数变化——哪怕与目标无关
（比如状态栏多了一个元素）——动作就被拒绝。这是有意的：误拒的代价是一次重读，
漏拒的代价是点错位置。误拒的实际频率**没有数据**，在验证阶段度量，
若过高再放宽（例如只核对到目标父节点那一层）。
夹具上已有一个具体实例（2026-10-18）：AX 把 `NSStackView` 摊平，往下方加一行就让窗口多一个子节点，
通往无关按钮的路径因此被拒绝。取值变化（标签文字）则不会误拒。
比例仍无数据，见 [夹具验证](../../verification/2026-10-18-fixture-validation.md)。

**比对发生在动作时，不是读取之后。** 读取与动作之间界面变了、但路径上的结构与目标核对键恰好不变，
这种变化检测不到（目标元素的值变化不在核对键内）。这是动作时比对的固有窗口期，
与[快照生命周期](../architecture/snapshot_lifecycle.md)中接受的窗口期一致。

**原生层多了一类请求，协议层多保存一棵树。** 换来的是原生层仍然无状态，
崩溃重启后协议层无需任何恢复。代价是内存里常驻一份快照；对一万五千个元素的树约为数 MB，P0 接受。

**句柄注册表决定后不受影响。** 若日后实现注册表，它建立在同一套定位器之上：
注册表只是把"句柄到定位器"的映射从单次读取扩展到跨读取。

## 后果

- 原生层线协议升到版本 3：`AXNode` 增加 `childCount`；新增请求 `performAction`；新增应答 `acted`、`located`、`stale`
- 错误码表补充 `action_failed`（平台拒绝了动作）；`target_switched`、`stale_snapshot`、`element_gone` 开始被使用
- `get_ax_state` 返回令牌；句柄在该令牌有效期内可用于动作
- 验证阶段需要度量误拒率与漏拒（见 [ADR-0013 出口门槛](adr_0013_p0_vertical_slice.md#出口门槛)的令牌项）
