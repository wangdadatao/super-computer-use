# ADR-0006 动作返回效果摘要

- **状态**：已接受，**部分被 [ADR-0011](adr_0011_convergence_over_fixed_delay.md) 修订**
- **日期**：2026-10-16

> **修订说明**：本文关于"何时判定效果"的部分已被
> [ADR-0011](adr_0011_convergence_over_fixed_delay.md) 取代。
> 效果摘要的字段定义仍然有效，但其中的"疑似空操作"字段改由收敛判定驱动，
> 不再依赖可配置的等待窗口。阅读本文的「取舍」与「后果」两节时请一并阅读 ADR-0011。

## 背景

既有实现的动作接口返回空值。观察到的两套实现都是如此：
动作成功即静默返回，不携带任何关于"实际发生了什么"的信息。

这留下一个反馈缺口。执行一个点击之后，判断是否生效的责任完全在调用方：
它必须重新读取状态，然后用自然语言推理判断界面是否按预期变化。

这个判断很容易出错，尤其是以下两类情况：

- **空操作**：事件成功投递，被点击的元素被禁用或不可交互，
  界面没有任何变化。调用方看到"调用成功"，容易误以为操作生效了。
- **焦点被夺**：点击生效了，但随即弹出了其他窗口或焦点被别的进程抢走。
  调用方读到的状态不是自己操作产生的。

这类失败是**静默的**——调用没有报错，状态看起来也合理，
只是操作没有达到预期效果。调用方往往要多轮之后才发现不对。

## 决策

**SCU 的动作接口返回结构化的效果摘要，而不是空值。**

摘要包含：

- 事件是否成功投递
- 无障碍树是否变化
- 目标元素的可观察属性是否变化
- 焦点是否被其他目标夺走
- 是否疑似空操作

字段定义见[协议总览](../interfaces/protocol_overview.md)。

**摘要只报告可观测的事实，不做意图判断。** 服务端不知道调用方
"想"完成什么，因此不返回成功/失败这样的结论，只返回可核对的外部观察。
意图是否达成由调用方判断。

## 取舍

**接受了每次动作的额外开销。** 计算效果摘要需要比对动作前后的状态，
这增加了一次状态快照的开销。对于不关心效果的场景（例如连续输入字符），
这是纯负担。

缓解方式：摘要中的状态比对可以复用已有的快照缓存，
且`treeChanged` 这类字段可以在不重新遍历整树的情况下得到
（通过无障碍服务的变更通知）。

**接受了区分"没变"和"还没变"的困难。** 有些动作的效果是异步的——
点击后触发网络请求，界面在几百毫秒后才更新。立即比对会得到
`noOpSuspected: true` 的误报。这需要一个有界的等待窗口，
窗口长度的选择是启发式的，无法对所有应用都正确。

这是本决策最脆弱的部分。若实测中误报率过高，
调用方会学会忽略这个字段，它将退化为噪声。缓解思路是
~~让等待窗口可配置，并允许调用方在明确知道动作是异步的时候跳过比对。~~

**（已被 [ADR-0011](adr_0011_convergence_over_fixed_delay.md) 修订）**
判定时机改由收敛窗口与稳定信号决定，效果摘要区分"已收敛无变化"与"未收敛"，
调用方不再需要自行猜测等待时长。

## 后果

- 动作接口不再是"发出即忘"，调用方需要处理返回的摘要
- 效果比对逻辑成为协议层的一部分，需要维护动作前后的状态快照
- `noOpSuspected` 的准确性直接影响机制的可信度，
  需要在真实场景下调优等待策略
