# macOS 权限

SCU 原生层运行所需的系统权限、检测方式与常见故障。

## 需要的权限

| 权限 | 用途 | 系统位置 |
| --- | --- | --- |
| 辅助功能（Accessibility） | 读取无障碍树、注入输入事件 | 系统设置 → 隐私与安全性 → 辅助功能 |
| 屏幕录制（Screen Recording） | ScreenCaptureKit 截图 | 系统设置 → 隐私与安全性 → 屏幕录制 |

两项都授予**可执行文件**，不是授予项目或终端会话。开发期直接运行脚本时，
需要给宿主程序（终端、IDE 或 Python 解释器所在的可执行文件）授权。

## 权限是前提

辅助功能未授权时，一切动作都会被系统拒绝。典型症状：

- 无障碍树读取返回空或权限错误
- 事件注入静默失败（无报错，但界面无反应）
- 坐标截图返回黑屏或纯色图

**静默失败是这里最大的坑**：事件注入在无权限时可能不报错。
因此原生层必须在动作前检测权限状态，而不是依赖调用失败来发现。

## 检测方式

```bash
# 辅助功能是否已授予当前宿主
osascript -e 'tell application "System Events" to get UI elements enabled'
# → true / false
```

屏幕录制权限没有等价的命令行查询。可行的做法是尝试一次最小捕获并检查
返回值是否为空图像，或查询系统权限数据库（需要额外权限，不推荐）。

## 本机状态

当前开发机上的检测结果：**辅助功能未授予**（`false`）。

在授权之前无法进行任何真实 UI 操作验证，包括[元素身份](../architecture/element_identity.md)
所依赖的无障碍树样本采集。

## 排障

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 树读取始终为空 | 辅助功能未授予，或目标应用拒绝暴露 | 先确认权限，再换一个原生应用测试 |
| 换了终端后失效 | 权限绑定到可执行文件 | 给新宿主任授权 |
| 授权后仍无效 | 系统缓存未刷新 | 退出并重启宿主进程 |
| 截图全黑 | 屏幕录制未授予 | 授予后重启宿主 |
| 某个应用完全读不到树 | 应用显式关闭了无障碍暴露 | 该应用无法通过 AX 路径操作，只能走坐标 |

最后一行是设计约束而非故障：**部分应用不会出现在无障碍树里**，
[ADR-0001](../decisions/adr_0001_accessibility_first.md) 的坐标兜底正是为此保留。
