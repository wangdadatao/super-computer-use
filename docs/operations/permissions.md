# macOS 权限

SCU 原生层运行所需的系统权限、检测方式与常见故障。

## 需要的权限

| 权限 | 用途 | 系统位置 |
| --- | --- | --- |
| 辅助功能（Accessibility） | 读取无障碍树、`AXPress` 点击（P0 已用）；注入输入事件（设计目标，P0 未实现） | 系统设置 → 隐私与安全性 → 辅助功能 |
| 屏幕录制（Screen Recording） | ScreenCaptureKit 截图（设计目标，P0 未实现也未检测） | 系统设置 → 隐私与安全性 → 屏幕录制 |

两项都授予**可执行文件**，不是授予项目或终端会话。开发期直接运行脚本时，
需要给宿主程序（终端、IDE 等启动 `scu` 的可执行文件）授权。

## 权限是前提

辅助功能未授权时，一切动作都会被系统拒绝。典型症状：

- 无障碍树读取返回空或权限错误
- 事件注入静默失败（无报错，但界面无反应）
- 坐标截图返回黑屏或纯色图

**静默失败是这里最大的坑**：事件注入在无权限时可能不报错。
因此原生层必须在动作前检测权限状态，而不是依赖调用失败来发现。

## 检测方式

```bash
scu permissions        # 走的是原生进程实际使用的路径；未授予时退出码 2
```

`osascript` 的查询（`tell application "System Events" to get UI elements enabled`）**不要用来判断**：
它走的是另一条路径，结果可能与原生进程不一致，见下文"本机状态"。

屏幕录制权限没有等价的命令行查询。可行的做法是尝试一次最小捕获并检查
返回值是否为空图像，或查询系统权限数据库（需要额外权限，不推荐）。

## 本机状态

**权限状态取决于运行命令的宿主，不是机器级事实。** macOS 的 TCC 按"负责进程"归属权限：
同一台机器上，从终端运行与从 IDE 内置 agent 会话运行，得到的结果可以不同。
`scu-native` 是 `scu` 的子进程，权限沿用启动链上的宿主。

用 `scu permissions` 检测——它走的正是原生进程实际使用的路径，比 `osascript` 更可信。

已观察到的结果（2026-10-16，macOS 26.6.2，arm64，同一台开发机）：

| 宿主 | `osascript` | `scu permissions` | 读取访达无障碍树 |
| --- | --- | --- | --- |
| Cursor 的 agent 会话（一次运行） | `true` | 已授予 | 成功 |
| 另一次 agent 会话（审计复现） | `false` | 未授予（退出码 2） | 未执行 |

两次结果不一致，**原因未查明**。符合 TCC 按宿主归属的解释，但没有进一步验证
（例如核对两次会话的负责进程）。结论只有一条：**不要假设某个宿主继承了权限，
每次在目标宿主里先运行 `scu permissions`。**

**作为 MCP 服务运行时**（`scu mcp`），宿主是启动它的 MCP 客户端，而不是你的终端。
在终端里 `scu permissions` 显示已授予，不代表 Cursor 等客户端启动的 `scu mcp` 也有权限；
让模型调用 `check_permissions` 才是在目标宿主里检测。

已观察到（2026-10-16，macOS 26.6.2，Cursor 经用户级 `~/.cursor/mcp.json` 启动 `scu mcp`，Cursor 版本未记录）：
`check_permissions` 返回已授予，随后读取访达的无障碍树成功。**只有这一个数据点**：没有核对负责进程，也没有其他宿主的结果。

未授予时，`scu permissions` 以退出码 2 结束，`scu dump` 报 `system_permission_missing`。
屏幕录制权限**尚未检测**，指示层隔离验证（B 组）需要它。

## 排障

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 树读取始终为空 | 辅助功能未授予，或目标应用拒绝暴露 | 先确认权限，再换一个原生应用测试 |
| 换了终端后失效 | 权限绑定到可执行文件 | 给新宿主任授权 |
| 授权后仍无效 | 系统缓存未刷新 | 退出并重启宿主进程 |
| 截图全黑 | 屏幕录制未授予 | 授予后重启宿主 |
| 某个应用完全读不到树 | 应用显式关闭了无障碍暴露 | 该应用无法通过 AX 路径操作，只能走坐标 |

最后一行是设计约束而非故障：**部分应用不会出现在无障碍树里**，
[ADR-0001](../decisions/adr_0001_accessibility_first.md) 的坐标兜底正是为此保留。
