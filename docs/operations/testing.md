# 测试策略

如何验证 SCU 的三个核心机制。当前无实现代码，本文描述计划中的验证方法。

## 三个待验证的假设

| 假设 | 属于 | 失败后果 |
| --- | --- | --- |
| 真实应用的无障碍树提供足够稳定的身份字段 | [元素身份](../architecture/element_identity.md) | 指纹碰撞或漂移，寻址退化为位置寻址 |
| 令牌失效能被及时且不误报地检测 | [快照生命周期](../architecture/snapshot_lifecycle.md) | 要么放行错误动作，要么频繁误拒 |
| 动作效果能被廉价地观测 | [ADR-0006](../decisions/adr_0006_action_effect_verification.md) | 效果回报变成噪声，调用方学会忽略它 |

前两个可以**离线验证**——只需要无障碍树样本，不需要真实执行动作，
因此不需要授予辅助功能权限即可开始。这是有意安排的第一步。

## 元素身份验证

**方法**：采集同一界面在受控变化前后的两份树，比对指纹。

采集点：

| 场景 | 变化类型 | 期望 |
| --- | --- | --- |
| 列表滚动一屏 | 元素增删 | 未滚动走的元素指纹不变 |
| 打开模态弹窗 | 层级变化 | 弹窗内元素为新指纹，背景元素指纹不变 |
| 切换标签页 | 内容替换 | 旧内容指纹消失，新内容指纹出现 |
| 输入文本 | 属性变化 | 输入框指纹不变，匹配结果为 `changed` |
| 窗口缩放 | 几何变化 | 全部指纹不变（几何不进指纹） |

**通过标准**：五类场景中，预期不变的指纹全部保持稳定，且无碰撞。

**失败处理**：若原生应用的 `AXIdentifier` 普遍缺失导致结构路径成为主依据，
需要在 [ADR-0004](../decisions/adr_0004_stable_element_identity.md) 中重新评估，
可能的退路是接受较低的稳定性并更频繁地要求重读。

## 令牌语义验证

**方法**：构造令牌失效的各种触发条件，验证上报的分类是否正确。

用例：

- 令牌有效时执行动作 → 应成功，不误报失效
- 界面变化后使用旧令牌 → 应拒绝，且分类为「树变化」
- 窗口移动后使用旧坐标令牌 → 应拒绝，且分类为「窗口变化」
- 切换目标后使用旧令牌 → 应拒绝，且分类为「目标切换」
- 重复使用同一失效令牌 → 只上报一次失效

**通过标准**：无漏报（不该执行的被执行了），无类别错报。

## 动作效果验证

**方法**：对已知会产生/不产生效果的场景执行动作，比对效果摘要。

| 场景 | 期望 `noOpSuspected` |
| --- | --- |
| 点击可用的按钮 | false |
| 点击被禁用（disabled）的按钮 | true |
| 点击被遮挡的元素 | true（或直接拒绝） |
| 在只读输入框输入 | true |
| 点击后触发耗时加载 | false（`treeChanged` 可能延迟） |

**难点**：区分「确实没变化」和「变化还没发生」。需要引入有界等待窗口，
窗口长度和收敛条件属于实现细节，待验证阶段确定。

## 不需要测试的部分

以下有意不纳入首版测试范围：

- 跨平台行为（Linux 尚未实现）
- 多目标并行（设计上不支持）
- 极端性能（当前无性能目标）
- 安全边界（策略层尚未设计，见[系统总览](../architecture/system_overview.md)的未定项）
