# 测试策略

如何验证 SCU 的核心机制。验证内嵌在 P0 中执行（见 [ADR-0013](../decisions/adr_0013_p0_vertical_slice.md)），
本文描述验证方法与通过标准。**核心机制已有最小实现，但假设尚未整体验证通过**：夹具上的令牌、效果、收敛、策略与身份 K4 已有结果，
见文末[当前状态](#当前状态)。
自动化测试分两类：工程测试（线协议、握手、否定路径、定位器、会话与策略、元素表与身份、MCP 管道与端到端）不属于本文的假设验证；
`FixtureTests`（真实原生层 + 真实夹具进程 + 真实 `AXPress`）是假设验证的自动化部分，结论见 [夹具验证](../../verification/2026-10-18-fixture-validation.md)。

## 待验证的假设

| 假设 | 属于 | 失败后果 |
| --- | --- | --- |
| 真实应用的无障碍树提供足够稳定的身份字段 | [元素身份](../architecture/element_identity.md) | 身份键漂移或多候选，寻址退化为位置寻址 |
| 令牌失效能被及时且不误报地检测 | [快照生命周期](../architecture/snapshot_lifecycle.md) | 要么放行错误动作，要么频繁误拒 |
| 动作效果能被廉价地观测 | [ADR-0006](../decisions/adr_0006_action_effect_verification.md) | 效果回报变成噪声，调用方学会忽略它 |
| 指示层能被可靠地排除出截图 | [虚拟指示层](../architecture/virtual_indicator.md) | 截图里出现幽灵元素，模型可能尝试操作它 |
| 收敛判定不产生大量误报 | [动作收敛与等待](../architecture/action_convergence.md) | 疑似空操作退化为噪声 |

### 验证的权限前提

**读取其他应用的无障碍树本身就需要辅助功能权限**，不存在"免权限采样"。
假设按所需权限分为两组：

| 组 | 需要的权限 | 覆盖的假设 |
| --- | --- | --- |
| **A 组** | 仅辅助功能 | 身份字段稳定性、令牌失效检测、收敛判定、动作效果观测 |
| **B 组** | 辅助功能 + 屏幕录制 | 指示层排除 |

A 组是成本最低的起点，只需要一项权限。其中身份字段稳定性可以只读采样完成；
令牌失效、收敛判定与动作效果观测需要在受控界面上执行真实动作（如点击）。
B 组额外需要屏幕录制权限。

两项权限的授予方式与检测方法见 [macOS 权限](permissions.md)。

## 准入与审批验证

**方法**：对三类动作各构造一组用例，验证三态结论及其区分度。

| 场景 | 期望结论 | 期望可区分性 |
| --- | --- | --- |
| 操作普通应用的可交互元素 | 允许 | — |
| 首次操作某应用 | 需确认 | 可识别为「待授权」 |
| 同一会话内再次操作同一应用 | 允许（命中会话级授权） | — |
| 操作终端类应用 | 拒绝 | 可识别为「命中拒绝类目」 |
| 操作实现自身 | 拒绝 | 同上 |
| 对拒绝类目重复请求 | 每次都拒绝 | **不得**因为重复而转为允许 |

**通过标准**：三态全部可区分；且**策略拒绝与协议拒绝在返回值上可区分**。
后一条是硬要求：调用方需要知道该重试（令牌失效）还是该放弃（策略拒绝）。

## 收敛判定验证

**方法**：构造不同时长的界面变化，检查收敛状态的判定。

| 场景 | 期望 |
| --- | --- |
| 点击后界面立即变化并停止 | 已收敛・有变化 |
| 点击禁用元素 | 已收敛・无变化，疑似空操作为真 |
| 点击后触发两秒的网络加载 | 等待期间不返回；稳定后返回已收敛 |
| 点击后触发无限动画 | 达到总上限后返回未收敛（**不得**无限等待） |
| 点击后界面不动但后台繁忙 | 已收敛・无变化（已知局限） |

**通过标准**：第 1、2、4 行必须符合预期；第 5 行是已知局限，不要求区分，但归属需在文档中明确。
第 3 行（两秒加载）不列为 P0 出口门槛，记为已知限制，见
[ADR-0013](../decisions/adr_0013_p0_vertical_slice.md#gate_revision_2026_10_19)；
已执行的结论仍记为"未满足"，不因该修订改记为通过。

## 会话清理验证

**方法**：在会话结束的各种路径下检查资源释放。

| 路径 | 需验证的释放 |
| --- | --- |
| 正常结束 | 指示层销毁、租约回落、按键释放 |
| 连接中断 | 同上 |
| 进程被强制退出 | 指示层不残留、租约被系统回收 |
| 拖拽中中断 | **鼠标按键被释放**，用户恢复对鼠标的控制 |
| 按住修饰键后中断 | **所有按键被释放** |

**通过标准**：任何路径下都不得把系统留在输入未释放的状态。
这一项失败的影响面超过 SCU 本身——它会直接影响用户使用电脑。

## 目标发现验证

| 场景 | 期望 |
| --- | --- |
| 同名应用两个实例 | 返回歧义错误，附候选列表 |
| 同一应用多窗口未指定窗口 | 返回歧义错误 |
| 多个标签页匹配同一 URL | 返回歧义错误 |
| 列表包含系统浮层 | 不包含 Spotlight、通知中心等 |
| 列表包含实现自身 | 不包含 |

**通过标准**：歧义一律报错，无隐式选择。

## 元素身份验证

**方法**：采集同一界面在受控变化前后的两份树，比对**身份键的匹配结果**与
**句柄的延续性**。观测对象是句柄——它是否被复用，以及是否出现多候选。

采集点：

| 场景 | 变化类型 | 期望 |
| --- | --- | --- |
| 列表滚动一屏 | 元素增删 | 未滚动走的元素句柄延续；滚动进来的分配新句柄 |
| 打开模态弹窗 | 层级变化 | 弹窗内元素为新句柄，背景元素句柄不变 |
| 切换标签页 | 内容替换 | 旧内容句柄转为「已消失」，新内容为新句柄 |
| 输入文本 | 属性变化 | 输入框句柄不变，匹配结果为 `changed` |
| 窗口缩放 | 几何变化 | 全部身份键不变（几何不进身份键），句柄全部延续 |

**通过标准**：

1. 五类场景中，预期延续的句柄全部延续
2. 同一快照内每个句柄唯一，不出现两个元素共用一个句柄
3. 落入 K4（依赖同级序号）的可交互元素比例满足
   [ADR-0013 的阈值](../decisions/adr_0013_p0_vertical_slice.md#k4-比例的口径与阈值)——
   这一比例直接决定身份方案的实际价值

**不测碰撞。** 句柄是递增计数器，同一会话内不可能碰撞——
需要测的是**身份键的区分力**：在什么情况下会产出多个同等候选。

**失败处理**：若原生应用的显式标识符普遍缺失，导致匹配主要依赖 K2/K3 的
祖先 role 路径，而该路径又因同 role 且同标题的兄弟过多而频繁落入 K4，
需要在 [ADR-0004](../decisions/adr_0004_stable_element_identity.md) 中重新评估。
可能的退路是接受较低的稳定性并更频繁地要求重读。

## 令牌语义验证

**方法**：构造令牌失效的各种触发条件，验证上报的分类是否正确。

用例：

- 令牌有效时执行动作 → 应成功，不误报失效
- 界面变化后使用旧令牌 → 应拒绝，且分类为「树变化」
- 窗口移动后使用旧坐标令牌 → 应拒绝，且分类为「窗口变化」
- 切换目标后使用旧令牌 → 应拒绝，且分类为「目标切换」
- 重复使用同一失效令牌 → **每次都拒绝**，失效迁移只记一次（[ADR-0015](../decisions/adr_0015_handle_resolution_by_path.md) §4）

**通过标准**：无漏报（不该执行的被执行了），无类别错报。

## 动作效果验证

**方法**：对已知会产生/不产生效果的场景执行动作，比对效果摘要。

| 场景 | 期望 |
| --- | --- |
| 点击可用的按钮 | `noOpSuspected=false`，`treeChanged=true` |
| 点击被禁用（disabled）的按钮 | `noOpSuspected=true`（平台可能不报错） |
| 点击被遮挡的元素 | 按下并产生效果（`AXPress` 不看遮挡，旧期望"拒绝或疑似空操作"已作废）；P0 按此判定 |
| 在只读输入框输入 | **不适用**：P0 没有输入动作 |
| 点击后触发耗时加载 | 不在此项判定：归入[收敛判定验证](#收敛判定验证)（该行不列为 P0 门槛） |

**难点**：区分「确实没变化」和「变化还没发生」。需要引入有界等待窗口，
窗口长度和收敛条件属于实现细节。P0 已取 200 毫秒轮询、连续两次一致、3 秒上限（启发式初值，见 [ADR-0011 追加记录](../decisions/adr_0011_convergence_over_fixed_delay.md)）；
夹具上"两秒加载"场景已被证伪（过早判为收敛）；2026-10-19 起它不列为 P0 出口门槛，记为已知限制
（[ADR-0013 追加记录](../decisions/adr_0013_p0_vertical_slice.md#gate_revision_2026_10_19)），不记为通过。

## 输入与按键验证

**方法**：对夹具的输入框执行输入与按键，检查值变化、令牌失效与提交行为（[ADR-0016](../decisions/adr_0016_input_and_keys.md)）。

| 场景 | 期望 |
| --- | --- |
| 向可编辑元素输入文本 | 值发生变化，`treeChanged=true`，令牌失效 |
| 输入后按 Return | 应用收到按键并执行绑定的动作（夹具的 status 变化） |
| 元素不接受焦点 | `unsupported_operation`，不投递事件 |
| 未知键名、空键名、多个主键 | 拒绝（`unsupported_operation`），不猜测 |
| 对可写元素设值 | 值变化，`treeChanged=true`，令牌失效 |
| 对不可写元素（如按钮）设值 | `unsupported_operation`，令牌保持有效 |
| 设空串 | 合法，表示清空字段 |
| 真实应用上的输入与输入法 | **未验证**；逐字输入没有 IME 处理 |
| 长按与跨动作保持修饰键 | v1 不支持；每个动作都是 down + up |

**通过标准**：前三行符合预期；后三行按"未覆盖/不支持"记录，不记为通过。

## 指示层隔离验证

**方法**：开启指示层，执行动作并截图，检查截图内容。

| 场景 | 期望 |
| --- | --- |
| 指示层可见时截图 | 截图中**不存在**指示层图形 |
| 指示层可见时读取元素表 | 元素表中**不存在**指示层窗口及其子元素 |
| 指示层可见时点击其覆盖位置 | 点击落到下层真实元素上，而不是被指示层拦截 |
| 关闭指示层后重复上述 | 结果一致（隔离机制不依赖于指示层是否存在） |

**通过标准**：四条全部成立。任何一条失败都是正确性问题，不是体验问题。

## 验证产物与标记约定

### 产物位置

验证产生的样本与结论放在仓库根目录的 `verification/`，**不属于文档库**——
它是证据，不是工程知识。文档库只描述当前结论，引用产物路径。

```
verification/
  samples/                    采到的无障碍树等原始样本（目前尚未使用，该目录不存在）
  YYYY-MM-DD-<主题>.md        单次验证或测量的记录（现有文件以主题命名，如 `2026-10-18-identity-k4.md`）
```

### 结论格式

每次验证写一个文件，至少包含：

| 项 | 内容 |
| --- | --- |
| 假设编号 | 对应上文假设表的编号 |
| 方法 | 用例、采样点、使用的命令 |
| 样本 | 指向 `samples/` 的路径与采集环境（应用版本、系统语言、窗口尺寸） |
| 结论 | 成立 / 不成立 / 部分成立 |
| 影响 | 若不成立，需要修改哪些文档或决策 |

**必须记录采集环境。** 无障碍树的表现随应用版本、系统语言、
窗口尺寸变化，"成立"这个结论脱离环境没有意义。

### 文档中的标记

假设被验证后，在相关文档的对应段落加一行标记：

```markdown
> **已验证**（YYYY-MM-DD）：见 verification/... 。
```

不成立的假设**不删除原文**，而是在同一位置加上推翻说明并链接验证记录——
保留被推翻的设计有助于理解为什么当前方案是现在这样。

## 不需要测试的部分

以下有意不纳入首版测试范围：

- 跨平台行为（Linux 尚未实现）
- 多目标并行（设计上不支持，见[会话与控制租约](../architecture/session_and_lease.md)）
- 极端性能（当前无性能目标）
- 领域数据访问（UI 自动化之外的能力已明确排除，见 [ADR-0010](../decisions/adr_0010_ui_automation_only.md)）
