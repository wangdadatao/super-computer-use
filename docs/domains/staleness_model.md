## 两类令牌的触发条件

### 快照令牌失效

| 触发条件 | 说明 |
| --- | --- |
| 树结构变化 | 元素增删或层级调整 |
| 窗口切换 | 目标窗口失焦或被替换 |
| 目标应用退出或崩溃 | 目标本身消失 |
| 会话切换目标 | 令牌作用域是会话，换目标即失效 |
| 显式重新读取树 | 调用方主动获取新快照 |

### 坐标令牌失效

| 触发条件 | 说明 |
| --- | --- |
| 目标窗口移动 | 屏幕坐标基准改变 |
| 目标窗口缩放 | 像素映射改变 |
| 再次截图 | 新的截图产生新的令牌 |
| 显示配置变化 | 分辨率或显示器布局改变 |

## 不触发失效的情况

刻意**不**视为失效的变化：

- **元素属性变化**：某个控件的值或文案变了，但指纹判定为同一元素。
  这是 `changed` 匹配结果，不是失效。
- **树的 diff 为空**：重新读取后树完全一致，令牌可以继续沿用。
- **调用方重试**：重试不改变令牌有效性，服务端按当前状态判断。
- **时间推进**：令牌没有绝对过期时间，只按状态变化失效。

最后一条值得说明：**不设 TTL。** 界面可能长时间静止，
按时间过期会强迫调用方做无意义的重新读取。失效完全由状态变化驱动。

## 上报语义

失效上报必须满足：

1. **结构化**：有独立的字段标明这是失效，而不是混在错误消息文本里。
2. **分类**：说明失效类别（树变化 / 窗口变化 / 目标切换），
   让调用方判断该重读树还是重新截图。
3. **不重复**：同一令牌在同一状态下只上报一次失效。
4. **不执行**：上报失效的同时，动作**没有**被投递到任何目标。

第 4 条是硬约束。宁可拒绝，不可执行到错误目标。

## 检测时机

失效应在**动作请求到达时**检测，而不是提前轮询。

理由：轮询无障碍树的成本远高于一次动作请求的比对成本，而且大多数动作
发生在界面静止期间，提前轮询是纯粹的浪费。

代价是存在窗口期——界面已变但服务端尚未察觉。在这个窗口期内，
调用方带着旧令牌发起动作会得到明确的失效回报，而不是一次错误的操作。
这是设计上接受的取舍。
