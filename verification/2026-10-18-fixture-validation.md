# 夹具验证：令牌、动作效果、收敛、策略（2026-10-18）

在自制夹具应用 `scu-fixture` 上，用真实的原生层、真实的 `AXPress` 与真实的辅助功能树，
对 [测试策略](../docs/operations/testing.md) 中的令牌、动作效果、收敛判定与策略四组场景做自动化验证。
本记录区分三类结论：**成立**、**不成立（缺口）**、**未覆盖**。

## 方法与环境

| 项 | 值 |
| --- | --- |
| 命令 | `swift test --filter FixtureTests`（18 个用例，串行，约 45 秒） |
| 夹具 | `Sources/scu-fixture/main.swift`：AppKit 窗口，按钮 Increment / NoOp / Disabled / AddRow / Delayed（2 秒后改状态）/ Animate（20 秒内每 100 毫秒改状态）/ Busy（3 秒后台 CPU，界面不变）/ Covered（被不透明视图覆盖） |
| 系统 | macOS 26.6.2，arm64，Swift 6.4 |
| 宿主 | Cursor 内置 agent 会话（辅助功能已授予）；测试在该宿主下运行 |
| 前置条件 | 夹具启动后等**连续三次读取结构一致**才开始（见下"启动期不稳定"）；真实访达与终端的两项用例依赖本机应用状态 |
| 参数 | 收敛轮询 200 毫秒，连续两次一致，总上限 3 秒（启发式初值，见 ADR-0011 追加记录） |

## 结果

### 令牌（假读取器 + 夹具）

| 用例 | 结果 |
| --- | --- |
| 有效令牌不误报 | 成立：界面不变时令牌沿用，`verify` 命中 |
| 路径上变化后旧令牌被拒，分类 `stale_snapshot` | 成立 |
| 切换目标后旧令牌被拒，分类 `target_switched` | 成立 |
| 重复使用失效令牌：每次拒绝，失效迁移只记一次 | 成立 |
| 别处**取值**变化（标签文字）不误拒目标 | 成立 |
| 同一容器里**加了一个兄弟**会拒绝目标 | **成立为"保守"，即误拒**，见下 |

### 动作效果与收敛

| 场景 | testing.md 期望 | 实测 | 结论 |
| --- | --- | --- | --- |
| 点击可用按钮（Increment） | 已收敛・有变化 | 约 6 次轮询内收敛，`treeChanged=true`，标签变为 `count: 1` | 成立 |
| 点击禁用按钮 | `noOpSuspected=true` | 平台**没有报错**，投递成功，`noOpSuspected=true` | 成立，但注意"投递成功"并不代表有效果 |
| 点击被遮挡的元素 | `noOpSuspected=true`（或拒绝） | `AXPress` **照常按下**，效果出现 | **与期望不符**：`AXPress` 不看遮挡，见"结论 2" |
| 点击后触发两秒加载 | 等待期间不返回，稳定后已收敛（有变化） | 约 0.43 秒判定已收敛、`treeChanged=false`；两秒后状态确实变了 | **不成立（缺口）**，用 `withKnownIssue` 固定 |
| 点击后无限动画 | 达到上限后未收敛，不得无限等待 | 约 3.6 秒返回，`converged=false` | 成立 |
| 点击后后台繁忙、界面不变 | 已收敛・无变化（已知局限） | 如期 | 已知局限，归属在文档中明确 |
| 在只读输入框输入 | `noOpSuspected=true` | — | **不适用**：P0 没有输入动作 |
| 静态文本上点击 | — | `unsupported_operation`（协议层、不重试），令牌保持 | 成立 |

### 策略

| 用例 | 结果 |
| --- | --- |
| 对 SCU 自身及其宿主祖先的动作 | 被拒绝，重复三次每次都拒绝，夹具状态未变 |
| 策略拒绝与协议拒绝可区分 | 成立：错误码、层级、可重试性均不同 |
| 真实终端按其真实 bundle id 被拒 | 终端未运行时用例直接返回，**该次未覆盖**；是否执行取决于本机状态 |

## 结论

1. **令牌四项成立，但误拒确实存在。** AX 树会把 `NSStackView` 摊平，
   "在下方加一行"在树里就是窗口多了一个子节点，通往 Increment 的路径被拒绝，而 Increment 本身毫无变化。
   这是 [ADR-0015](../docs/decisions/adr_0015_handle_resolution_by_path.md) 预期的保守取舍，现在有了一个具体实例；
   **误拒率**（在真实应用的真实使用中有多大比例）仍未度量，所以"令牌"门槛**仍不记为通过**。
2. **`AXPress` 不看遮挡。** 被不透明视图盖住的按钮仍然被按下。testing.md 里"被遮挡的元素 → 疑似空操作"
   这一行的前提（动作会失败或无效果）不成立：对 `AXPress` 来说，遮挡既不被拒绝也不被识别。
   这不是缺陷而是该动作方式的性质，但意味着依赖 `AXPress` 的调用方**不能**把"点击成功"理解为"用户看得见、点得到"。
3. **两秒加载被过早判为收敛，缺口成立。** 两次一致的判定看不到尚未发生的变化。
   这是收敛验证第 3 行的**未满足**项；在引入加载信号或更长的观察窗口之前，P0 的收敛门槛**不能记为通过**。
4. **启动期不稳定是真实现象，不只是夹具问题。** 刚启动的应用树仍在变化（窗口控件与菜单陆续出现），
   在这期间读取、再点击，会把启动期的变化当成点击的效果：本轮第一次运行里，所有"空操作"场景都因此误报为"有变化"，
   最后靠"等三次读取一致"才得到干净结果。真实使用中同样会出现，调用方（或将来的工具）应当对刚启动的应用先等稳定。
5. **清理门槛不适用。** P0 的点击只用 `AXPress`，没有注入输入、没有按键保持、没有拖拽，没有需要清理的状态；
   这一项记为**不适用**并写明原因，不记为通过。

## 未覆盖

- 夹具以外的真实应用上的 `press` 投递：**未覆盖**。访达上只做过 `verify`（不点击），`SessionTests` 的 press 走假读取器；Electron 应用未试。
- 动态界面下的误拒率。
- 收敛阈值（200 毫秒 / 3 秒）的合理性。
- 终端用例在终端未运行时不执行。
